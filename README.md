## 五、数据治理详解（load_data.py）

治理原则：**治理规则先于分析**——不先把口径定干净，分析结论全是错的。

原始 1,067,371 行 → **有效 779,407 行**，五条规则：

| # | 规则 | 为什么 | 影响行数 |
|---|---|---|---|
| 1 | 全字段去重 | 重复行会双计 GMV | -34,335 |
| 2 | **取消单双条件识别**：Invoice 以 C 开头 **或** Quantity < 0 | 取消单混入会虚增收入；双条件比单条件（仅 C 开头）多识别 3,456 行退货 | -19,104 |
| 3 | 剔除非正数量（Quantity ≤ 0） | 负数为退货，非销售行为 | 合并至上条 |
| 4 | **剔除 Price < 0.01** | 原始数据存在 £0.001 级脏价格；`round(2)` 后会变成 0 金额，导致后续 `log(0)` 崩溃 | -18 |
| 5 | 剔除无客户 ID 行 | 无法归属用户，RFM / 复购分析会漏算 | -228,508 |

> 第 4 条是实战踩坑：见[工程踩坑记录](#九工程踩坑记录)。

## 六、指标体系（三层分解）

以**月度净 GMV** 为北极星指标，恒等式分解：

```
月度净 GMV ＝ 活跃客户数 × 人均订单数 × 客单价
```

- **恒等式校验**：三个因子乘回去必须等于原 GMV（SQL 第 9 段逐月验证通过）——这是防拆解错位的保险
- **下钻逻辑**：任何 GMV 异动都能归到三个因子之一——来人少了 / 买得少了 / 客单低了
- 核心指标字典：GMV、订单数、购买人数、客单价、活跃客户数、人均订单数、复购率（客户口径）、渠道结构、国家结构、RFM 三维、同比 / 环比、7 日移动平均

## 七、11 段分析 SQL 逐段详解

> `analysis.sql` 全部基于 **CTE + 窗口函数**（LAG / ROW_NUMBER / NTILE / RANK / ROWS BETWEEN），
> 是真实数仓取数的核心写法；迁移到 Hive / SparkSQL 只需改表名。

### 第 1 段 · 治理概览
统计有效行数 / 客户数 / SKU 数 / 订单数 / 覆盖周期 / 总 GMV——一切分析的起点。
**产出**：779,407 行 / 5,878 客户 / 4,630 SKU / 36,969 单 / GMV £17.37M。

### 第 2 段 · 月度经营趋势
按月聚合 GMV、订单数、购买人数、客单价。
**发现**：月度 GMV 呈双峰结构——2010-11（£1.17M）与 2011-11（£1.16M）为年末礼品季峰值，6 月与 9–10 月为次高峰。

### 第 3 段 · 国家维度
`SUM(amount) / SUM(SUM(amount)) OVER ()` 窗口占比。
**发现**：英国 £14.39M（82.8%）绝对主导；EIRE / 荷兰 / 德国为前三大海外市场——海外市场有增量空间但客户数极少（荷兰仅 22 家），呈大客户特征。

### 第 4 段 · 商品维度
Top15 热销商品 GMV / 销量。
**发现**：REGENCY CAKESTAND 3 TIER（£277.7K）居首；POSTAGE / Manual 等非商品行混入——真实业务数据常见的「脏维度」，治理时需与业务确认是否剔除。

### 第 5 段 · RFM 用户价值分层
`NTILE(5)` 五分位打分（R 反向），按业务语义分 6 类人群。
**发现**：重要价值用户 1,344 人（22.9% 人数）贡献 £11.95M（68.8% GMV），人均 £8,894、16.6 单；重要挽留用户 394 人平均沉默 366 天——高价值流失人群，召回优先级最高。

### 第 6 段 · 复购分析（口径修正示范）
**先按「客户 × 订单」去重，再用 `ROW_NUMBER()` 按用户分区标记首单 / 复购**。
**发现**：5,878 位客户全部有首单、复购率 72.4%、人均 6.29 单、单用户最多 398 单。
> ⚠️ 这里是本项目最重要的口径修正：事实表是**订单行明细**，直接 `ROW_NUMBER` 会得出 99.25% 的「行口径复购率」——错误结论。正确做法先去重再编号。

### 第 7 段 · 月度 Cohort
首购月份对齐，逐月拆新客 / 老客复购。
**发现**：老客占比从 2010-01 的 46.8% 爬升至 2011-04 的 87.6%——老客基本盘扩大，但新客获取在萎缩（与第 11 段互为印证）。

### 第 8 段 · 日 GMV 异常监测基准
`LAG` 环比 + `ROWS BETWEEN 6 PRECEDING` 7 日移动平均；3σ 判定在 Python 侧完成。
**发现**：604 个交易日中 6 天偏离均值 3σ 以上，集中在 2010-09~11 与 2011-09（旺季前备货）及数据截止日 2011-12-09（£184.3K 单日峰值）。

### 第 9 段 · 三层分解（恒等式校验）
逐月输出活跃客户数 / 人均订单数 / 客单价，并验证三者乘积等于当月 GMV。
**产出**：指标体系底座，恒等式 25 个月全部校验通过。

### 第 10 段 · 环比 vs 同比
`LAG(gmv)` 环比与 `LAG(gmv, 12)` 同比对照。
**发现**：环比噪声极大（2011-03 环比 +33.2%），同比才能反映真实经营变化——**监控口径应弃用环比改用同比**。
**另**：末月 2011-12 仅 1–9 日数据，按整月口径会出现 -41.4% 的「假异动」，监控时必须显式剔除截断窗口。

### 第 11 段 · 月度新客 / 老客 GMV 拆解
首购月份对齐，按客群拆 GMV / 客户数 / 人均。
**核心归因结论**：2011-04 同比 -20.9% 中，新客 294 → 106 人（-63.9%）、GMV £116.9K → £41.1K；老客 648 → 750 人（+15.7%）、GMV £446.9K → £427.3K——**下滑根因在新客端（拉新），不在老客端（留存）**。据此建议：优先复盘拉新渠道效率，不动留存预算。

## 八、统计检验详解（run_analysis.py · scipy）

**问题**：2011-04 的订单金额是否显著低于其他月份？差异是否值得业务投入？

**方法链**：

1. **对数变换**：订单金额强右偏（少数 B2B 大额订单，最大 £168,469.60），直接 t 检验违反正态假设；取 `log(amount)` 后接近正态
2. **Welch t 检验**（不假设等方差）：t = 0.692，**p = 0.489，不显著**
3. **Mann-Whitney U 检验**（不假设分布）：U = 8.59e9，**p = 0.0036，显著**
4. **Cohen's d**（效应量）：**d = 0.005**——远小于 0.2 的小效应阈值

**结论解读（本项目的分析价值观）**：
> 两个检验结论相反，恰恰说明不能只看 p 值。Mann-Whitney 对分布形状敏感故显著，
> 但 Cohen's d = 0.005 意味着两分布几乎完全重叠——**统计显著只说明差异存在，效应量才说明差异值得管**。
> 据此给出「不建议针对该差异投入资源」的判断。

**样本量测算**（run_analysis.py 附带）：
按月复购率口径（当月活跃且上月也活跃）基线 38.84% 测算，检出 +10% 相对提升所需每组样本约 2,513 人——实验设计前先算样本量，避免「测了但没功效」。

## 十、核心发现与业务判断汇总

1. **口径先行**：GMV 强季节性 → 弃环比改同比；末月截断 → 剔除假异动；订单行明细 → 复购先去重再编号
2. **归因为果**：2011-04 同比 -20.9% 的根因是新客端（-63.9%）而非老客端（+15.7%）→ 复盘拉新，不动留存
3. **统计克制**：Cohen's d = 0.005 → 统计显著但业务微弱 → 建议不做投入（敢说「不做」也是分析价值）
4. **异常可解释**：3σ 异常日全部可归因（旺季备货 / 截止日大单），非随机故障
5. **结构有空间**：英国占 82.8%，前三大海外市场客户数极少但人均 GMV 高——海外大客户深耕是潜在增量

## 十一、工程踩坑记录（真实复现过程）

1. **`round(2)` 制造 0 金额**：原始数据存在 Price = £0.001 的行，`Quantity × Price` 后 `round(2)` 变成 0，导致 `log(0) = -inf`、Welch t 返回 nan。修复：清洗规则加 `Price >= 0.01`（最小货币单位），金额保留 4 位小数
2. **复购率口径错误**：事实表是订单行明细，直接 `ROW_NUMBER` 按行编号得出 99.25% 的「行口径复购率」。修复：先 `DISTINCT (客户, 订单)` 再编号，得客户口径 72.4%。**教训：算用户级指标前先想清楚事实表粒度**
3. **数据集下载**：UCI 源在国内约 10KB/s 且频繁断流（45.6MB 实测 78 分钟），`download_retail.py` 带 60 轮断线重试才跑完；HF 镜像 CDN、ghproxy、Kaggle API 均实测不可用或更慢
